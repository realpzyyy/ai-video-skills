# AI 口播精剪：音频先行，两次确认

默认流程：**读取/转写 → 逻辑与句级精简 → 音频试听确认 → 视频剪辑时间线（不导出粗剪MP4）→ 3×3风格配色确认 → 一次最终合成与检查**。不默认加封面，不再强制第三次动态样片确认。

这是制作规范、可复用视觉母版和轻量辅助脚本，不附带 ASR 模型或云插件。V2.2 增加受授权的依赖安装器：先复用，缺失时安装 FFmpeg/FFprobe 与固定版本 Remotion，再验证；不把 node_modules 打进 Skill。沿用已有工程/用户批准项；局部修改只处理受影响范围。本轮请求优先于历史流程。

## 入口与按阶段读取

0. **安装、更新、环境准备或依赖缺失**：先读 [安装与环境初始化](references/setup.md)。用户已明确授权安装必要依赖时，运行 scripts/setup_runtime.py --install，不再只报缺失或逐包重复询问；未授权则只 --check 并请求所缺安装范围。安装完成必须做合成测试，记录 runtime-report.json 的实际路径。Skill 导入本身不保证会执行安装脚本，安装 Agent 必须显式执行此步骤。此步骤不需要用户原片，不触发 G1/G2。
1. 新项目读 [预检](references/preflight.md)、[记录](references/project-record.md) 和 [速度预算](references/performance.md)。只查本阶段必要能力；同一未变环境复用证据。已有项目先读当前记录，不重扫全盘。
2. 内容与音频读 [内容 SOP](references/content-sop.md)：源语言逐字稿、逻辑分层、语义精简、字音与切口复核；只输出音频供用户确认。
3. 音频确认后读 [风格系统](references/style-system.md) 和 [标准模板](references/standard-templates.md)：复用包内磨砂工具箱、纸白知识杂志、精密流程科技三母版，各配奶油杏橙、晴空钴蓝、香芋青柠；生成本次同内容/真人九格，暂停让用户选定组合。不能临时替换成简陋卡片。
4. 风格配色确认后读 [视觉 SOP](references/visual-sop.md) 与 [交付](references/acceptance.md)：复用模板、做必要内部验证，直接合成最终视频。不把内部 QA 再变成默认审批。
5. 用户另选内容传播优化时才读 [可选优化](references/optional-optimization.md)。不为制作默认查运营文章或平台热点。
6. 改维护流程时读 [行为检查](references/validation-scenarios.md)。脚本说明随对应阶段路由，不要求执行前读所有文件。

外部执行后端确定后读取其当前可用指南/工具 schema。遵守宿主对图像、音频、浏览器操作的路由，不借本 skill 绕过。指令、工具可见、依赖存在、实际成功是不同证据。

## 两个默认确认点

| 确认点 | 交付给用户 | 暂停边界 |
| --- | --- | --- |
| G1 音频 | 完整精简音频 + 简短剪后稿/删改摘要；列出关键疑点 | 必须确认内容、完整性和听感后，才继续视频时间线及风格制作 |
| G2 风格与配色 | 9 组真实可实现静态合成样张；A1–C3 编号及推荐组合 | 用户选定完整组合后，直接进入最终包装与烧制 |

若只选了风格、没选配色，补问配色，不擅自认定默认色。已有相同视频的有效音频/风格确认可复用。用户明确要求免确认才可跳过等待，记录“用户授权跳过”，不能写“用户已试听/选定”。用户要求先看动态才增加动态确认。

**这是执行边界，不是事后问卷**：G2 未获回复时必须结束当前轮等待，不能一边提问一边烧制，也不能先出成片再问喜欢什么风格。批量资产与最终编码前执行 scripts/check_gate.py；记录必须来自本视频的真实用户消息，绑定音频/时间线、候选板与模板版本。只推荐、只点开候选或另一个视频的批准都不成立。校验器是辅助一致性检查，不能代替宿主遵守确认规则。

## 不可丢失的质量约束

- “最精简”指**保留完整原意且原声自然的最短可用表达**，不是字数最少。删重复、口误、跑题和组织语言痕迹；重要条件、否定、事实限定、因果、必要主语/序号不能丢。
- “然后、就是、那个、这个、呃、啊、嗯”等是审查候选，不是全局替换表。清理无意义气口与犹豫声，保留必要呼吸、断句及有语义的用词。
- 文字顺不等于声音顺。优先短语/句子级顺序选段；不为拼出润色稿反复拆字、倒接、削弱起音。原片没有的表达标需补录，不以字幕或默认 TTS 冒充。
- 原声音频、视频剪辑、字幕与 B-roll 共用一个源时间映射；交叉淡化若造成时间重叠，视频接点/字幕必须用有效输出映射，不能简单累加片段时长。
- 原声确认后锁定版本。视频包装不改速、不改声线、不额外删音；更改原声必须重开 G1 并使受影响下游记录失效。
- 实际人物来自原片，不默认重绘脸。含背景的真人窗口不是抠像；背景专用蒙层要有真实人物分离能力。
- B-roll 必须解释内容、提供真实证据/情境或覆盖视觉剪口。概念示意不可冒充真实软件界面、数据、作品或录屏。
- 保持字体、配色角色、材质、光照和图标一致；运动服务信息，不靠所有元素持续跳动造“高级感”。
- 预览与成片共用 assets/studio.css、studio.mjs 的母版；移植后端需核对等价。竖线、姓名标签和小字黑条不是内容 B-roll。38px/720基准字幕、语义分 cue、独立对象关系与动作详见标准模板，不能为提速静默回退默认字幕。
- 看图、听音、生成、代码绘图、渲染是独立能力；转写/波形不证明已听审，代码/成功退出不证明美术通过。
- 快速不是静默降质或越权。普通剪辑请求不默认授权新增安装；用户已明确要求的运行依赖按 setup.md 安装，不重复征求同一范围。付费、管理员提权、下载大模型、私有素材云上传、声音克隆和公开发布仍需分别授权；封面不在默认交付里。

## 速度与交付

约1分钟常规口播，在依赖/模型已就绪、已有模板、两次确认无需返工的条件下，以**累计主动处理 ≤600秒**为优化目标，包含模型分析、调用等待、渲染与必要 QA；用户暂停时间单独记录。冷启动单列且计入真实总耗时。未跑端到端基准前不得承诺已稳定达标；原片很长、复杂分割/生成或返工需重新估时。

常规路径只进行一次最终视频编码；音频阶段不导出粗剪 MP4，风格阶段不渲染9条视频，默认不单独编码 G3 样片。短段内部测试或必要修复可额外渲染，记录原因，不以次数限制阻止纠错。

交付实际 MP4、SRT（后端可独立导出时）、真实可编辑时间线/工程与简短 QA/耗时说明。HTML 不是视频，Remotion/选段表不是剪映原生草稿。保留原片和历史结果，不自动发布或修改远端 Skill。
