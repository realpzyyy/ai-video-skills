# 快速路径与耗时口径

## 目标及边界

默认性能目标：常规约1分钟单人口播，累计主动处理不超过600秒，取得可检查的首版最终成片。不是承诺任意硬件、任意原片或任意返工都能10分钟达到主观满意。

适用条件：约60–90秒以内原片；720p/1080p、常规帧率；已有本地/获准后端、ASR缓存模型、字体、渲染模板；无额外下载、复杂人像分割/写实生图/声音生成；两次确认通过。分辨率和质量仍按用户要求，不能偷偷降到更低规格以达标。

分别记录：
- active_elapsed：分析、工具编排、工具/云队列等待、渲染、QA的累计处理墙钟时间；并行任务按区间并集，不能简单相加，也不能只统计编码器时间。
- user_wait：明确提交G1/G2后等待用户的时间；另计，不算主动处理。
- cold_start：安装/下载/首次构建或模型加载时间；是主动处理区间内的标记子集，单列但不能与active重复相加；纳入真实端到端总耗时，不隐瞒为“环境问题”。
- total_elapsed：从接收到交付的真实墙钟时间。修订次数和返工原因一并记录。

## 600秒阶段预算（工程目标，不是测量结果）

| 阶段 | 预算 |
| --- | ---: |
| 预检、提取音频、读取缓存/转写 | 90秒 |
| 逻辑精简、选段、字音和切口复核 | 120秒 |
| 音频输出与必要检查，提交G1 | 30秒 |
| 视频时间线 + 3×3风格静态板，提交G2 | 60秒 |
| 模板填充、字幕与B-roll、内部代表帧检查 | 75秒 |
| 最终视频合成与音轨封装 | 180秒 |
| 最终解码/抽帧/同步核验与交付 | 45秒 |
| 合计 | 600秒 |

预算不是到点跳过检查。阶段超预算先识别原因；预计总时长超标，报告瓶颈、剩余估时和现有成果。若改风格/质量/外传范围才能提速，先取得相应确认。

## 去除实际重复工作

1. **音频先行**：G1前只做音频，不再每次声音修订都重编码完整视频。
2. **同一分析产物**：一次转写，一份校对层，一份精简脚本，一条源映射。疑点用短窗口复查；不因字幕生成或换颜色再整片ASR。
3. **两次确认**：一轮试听、一轮A1–C3选择。默认不另做“先选风格再选颜色”两轮，也不再强制动态样片审批。内部运动检查仍保留。
4. **三套组件，不是九次创作**：每套风格共用构图/字体/对象/动画，只替换三组颜色角色。用一次页面或批量静帧渲染出九格；不得给九套独立动画或调用九次生图。
5. **先找可复用入口**：复用已安装运行时、现有渲染器、参数化素材与字体缓存，不每条视频重新搭项目、安装依赖或重新做画风研究。
6. **构建一次**：一次bundle/预览服务可批量出所需静帧及最终输出；不为了每个帧重复启浏览器/构建。外部素材先就位，避免public媒体符号链接在打包后丢失。
7. **一次最终视频编码**：渲染器直接从原片+选段读取画面；画轨静音，再封装已确认音频。不能为了“纯粗剪→样片→正式片”把全片逐级重复编码。
8. **按风险QA**：音频先完整听审；最终检查全部字幕文字、全片解码及音画映射，并抽查首尾、最长字幕、切口、B-roll入/落/出。普通改色不重新逐帧生成几百张对照图。发现异常再扩大范围。
9. **复用预检，不省掉预检**：换agent/宿主时验证当前必需工具和资产；同环境已成功的证据直接引用。只有变化或失败才重扫相关项。
10. **沟通紧凑**：每阶段一次摘要+实际产物，不反复长篇说明、重复读全部参考或为小修改另写整套说明书。源映射/QA留在结构化文件。

## 渲染速度怎么判断

先用缓存命中状态和当前后端的代表片段做小测试。测试应包含真实视频解码、字幕和复杂B-roll，记录分辨率、fps、编码器、并发、构建时间、样本帧数与速度；纯色动画/无音轨测试不能代表完整生产。

若用抽样外推，明确标估计并留余量，不能声称“全片实测10分钟”。硬件编码是否更快/可接受，用本机实际可用编码器和画质样本验证，不照抄GPU或并发参数。没有缓存或代表模板时记录冷启动，避免无限试错。

## 基准与缓存

缓存键至少包含源身份（路径/大小/mtime，必要时hash）、ASR模型/语言/版本、timeline_revision、style_id、palette_id、模板/字体/资产版本、输出规格。源或参数变更使对应缓存失效。临时产物单独目录，不覆盖用户确认版。

记录到project.performance或一个timings.json即可，避免为每次命令生成独立报告。只有**完整原片输入→G1音频→G2九格→最终MP4→必要QA**的实际运行能作为端到端达标证据。不同机器/模型/工具的速度不得沿用为通用保证。
